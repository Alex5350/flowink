# Glossary

Terms used across FlowInk's documentation: plain English first, precisely second.

| Term | In plain English | Precisely |
|---|---|---|
| Animated diagram | A flow diagram that moves: dashes march along the lines so you can see which way things flow, dots ride the paths, and box borders gently breathe. The movement shows direction; the colors and words carry the meaning. | An SVG whose flows animate via CSS (dash-offset marching, opacity pulses, Motion Path packets) with a static base layer always drawn, so the diagram stays complete when animation is frozen. |
| Spec-as-data | The diagram is written down as a plain data file (a JSON document listing the boxes and arrows), not drawn by hand in a tool. Like a recipe versus a photo of the meal: the recipe can be checked, changed, and cooked again. | A `FlowSpec` JSON document (nodes with manual coordinates, edges with colors, labels, directions, packets) that the renderers turn into SVG; it diffs line by line and regenerates deterministically. |
| GitHub-safe rendering | The picture works everywhere a README works. GitHub shows README images through a locked-down image loader, and output that respects those rules animates there instead of turning into a blank box. | Output contains no scripts, no SMIL, and no external references (system font stacks), so it renders in Chromium's SVG-as-image path and any other `<img>` context; SMIL plus a `<style>` block is the combination that paints nothing there ([ADR 0001](adr/0001-css-only-animation.md)). |
| Reduced-motion respect | People who have told their devices "fewer movement, please" get a diagram that holds still, and they lose nothing: the same boxes, lines, colors, and words, just no marching. | The generated stylesheet includes a `prefers-reduced-motion: reduce` block that disables all animation; meaning is never encoded in motion alone. |
| SMIL | The animation feature built into the SVG format itself. It is the obvious tool, and it is the one that silently blanked four READMEs: combined with a stylesheet it makes the way GitHub loads images paint nothing at all. | SVG's native animation elements (`<animate>`, `<animateMotion>`, `<animateTransform>`); structurally banned from FlowInk's output, with tests asserting their absence on both stacks ([ADR 0001](adr/0001-css-only-animation.md)). |
| CSS-only animation | Animating with the same stylesheet techniques web pages use, inside the SVG. Less powerful on paper, but it survives every place the diagram needs to live. | Keyframed `stroke-dashoffset` for flows, opacity for pulses, and `offset-path` (CSS Motion Path) for packets; the renderer has no code path that could emit SMIL. |
| Byte parity / golden fixture | The TypeScript and C# versions must produce the exact same output, down to the last character, and a committed reference file proves it on every test run. Like two printers required to print the identical page, checked character by character. | A committed TypeScript-rendered SVG ([dotnet/tests/FlowInk.Tests/fixtures/parity-ts.svg](../dotnet/tests/FlowInk.Tests/fixtures/parity-ts.svg)) against which the C# suite asserts whitespace-normalized equality; drift fails CI ([ADR 0002](adr/0002-spec-parity.md)). |
| RSC / SSR-safe | The React diagram renders on the server, inside the newest Next.js page style, without needing any JavaScript in the browser. The picture arrives fully drawn. | The component is a pure function of props, emits no client JavaScript, and renders identically in React Server Components, server-side rendering, and client components; `renderFlowToString` covers build-time output. |
| ng-packagr / FESM | The machinery that turns Angular source code into the kind of package an app can actually install. Shipping raw source instead is why the first real consumer's install failed. | The Angular library compiler producing a FESM2022 bundle plus types with proper entry points; the Angular application builder does not compile TypeScript inside `node_modules` ([findings F1](findings-first-consumer-validation.md)). |
| Peer dependency | "You bring the engine, I'll bring the part." The component package expects the app to have the core renderer already, so there is never a second, slightly different copy of it. | `@flowink/core` declared in `peerDependencies` for `@flowink/react` and `@flowink/angular`, avoiding duplicate renderer instances; while unpublished, install the tarballs in one command. |
| esbuild bundle | The command-line tool is welded into a single self-contained file: install it anywhere and it works, with nothing else to download. | The CLI bundles `@flowink/core` via esbuild into one `dist/cli.js` and declares zero runtime dependencies, so global installation never resolves against a registry ([findings F3](findings-first-consumer-validation.md)). |
| Injection trust boundary | A rule that keeps diagram text as text, always. Whatever someone types into a spec, it can only ever become visible words, never a running script. | The entire output document is built from hard-coded templates plus XML-escaped, runtime-coerced spec content (clamping `safeInt` on every numeric, escaped `path` data); no code path leads from spec fields to executable content ([ADR 0004](adr/0004-injection-trust-boundary.md)). |
